# 《花事》v4.0 花束美术馆设计说明

日期：2026-08-09
版本：v4.0

## 1. 核心判断

现有网站的问题是“在介绍花”，而不是“在欣赏花”。单独一朵野花很难直接给人直观的美感，花店里的大花束反而更接近大多数人感受到的“美”。

v4.0 把产品逻辑倒过来：

- 先给一束花，再让人认识里面的花
- 先让眼睛产生好感，再让知识成为第二层
- 页面像一座数字花束美术馆，而不是一本花卉百科

## 2. 页面结构

1. 封面：一束花占据整屏，只有刊名与一句邀请
2. 花束美术馆：16 束花以大幅版面出现，每束配名字、情绪、一句话提示词
3. 花束档案：点开任一花束，看到大图、花材拆解、为什么好看、故事与生成提示词
4. 送花时刻：按“送给谁、想说什么、希望什么感觉”推荐一束花
5. 我的花事：保留时间线，收藏对象从“一朵花”升级为“一束花”

## 3. 内容原则

- 花束是主角，单花是花束里的“花材”
- 每束花先给一句让人心动的观察，再给知识与故事
- 文案避免词典感，使用“观赏语言”：颜色、姿态、光线、氛围
- 保留 16 束花束提示词，每束提示词都可复制
- 保留图片来源与授权标注

## 4. 数据模型

```js
{
  id: "red-rose-confession",
  name: "红玫瑰 · 告白",
  mood: "热烈",
  occasion: "告白",
  image: "images/rose-bouquet.jpg",
  alt: "一束红玫瑰花束",
  prompt: "一束浓烈的红玫瑰……",
  why: "红玫瑰的好看在于……",
  flowers: ["玫瑰", "尤加利"],
  story: "第一次送花……"
}
```

花材详情复用 12 种单花资料，作为花束档案里的“拆解层”。

## 5. 视觉系统

- 高级观赏型 UI：花束大图为主，文字退后
- 近黑底与淡绯色保留，但不再用密集卡片
- 花束以整幅版面呈现，像美术馆展墙
- 使用大号衬线标题、细线、少量动效
- 移动端保持单列大图，不牺牲花的尺寸

## 6. 交互

- 花束大图点击进入花束档案
- 档案内可切换花束、复制提示词、收藏
- “送花时刻”结果推荐一束花，并可收进我的花事
- 相关花束按情绪与花材相似度推荐

## 7. 验收标准

- 桌面 1440px 与手机 390px 无横向溢出
- 全部图片可加载
- 16 束花均可打开档案并复制提示词
- 测试推荐花束、收藏、时间线完整可走
- 无控制台报错

## 8. 不做的事

- 不把单花列表放回首页
- 不新增购物车或真实购买流程
- 不改变图片来源与授权规则
